# Compuerta de continuidad de CTA

## Propósito

Evitar CTAs genéricos, sobredimensionados o desconectados del bloque que los precede. Un CTA cierra una decisión ya construida; no reinicia la pieza con un mandato intercambiable.

## Cuándo se usa

En toda landing, email, post, story, reel o estado comercial de UX que incluya una acción visible.

## Gate bloqueante

1. **Consecuencia directa:** el texto del CTA es el siguiente paso lógico de la frase o bloque inmediatamente anterior.
2. **Acción real:** nombra una acción disponible en VMC sin prometer propuesta, venta, dinero, resultado o plazo.
3. **Especificidad suficiente:** evita genéricos como `Conoce más`, `Haz clic aquí`, `Empieza ahora` o `Publica ahora` cuando el contexto permite nombrar el objeto o decisión. Una acción real no basta si podría aparecer debajo de cualquier bloque de esa misma landing.
4. **Brevedad funcional:** por defecto usa de una a cinco palabras y no intenta repetir toda la promesa del hero. La longitud puede cambiar solo si el elemento de interfaz lo exige.
5. **Progresión:** si hay más de un CTA, cada uno responde al bloque local; no se repite una misma etiqueta por inercia.
6. **Tono:** conserva la energía de la pieza sin exclamaciones decorativas, presión o FOMO inventado.

## Resultado

`EVIDENCE_READY` exige seis respuestas afirmativas. Un CTA correcto como acción pero ajeno al bloque anterior recibe `REWRITE`.

```text
Bloque anterior:
CTA:
Conexión de decisión:
Acción real / límite factual:
Resultado: EVIDENCE_READY / REWRITE / VETO
Corrección estructural:
```
