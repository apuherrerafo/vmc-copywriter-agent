# Copy para stories

## Propósito

Convierte o mejora el copy de una story existente en una secuencia breve y entendible pantalla por pantalla. Cada pantalla debe cumplir una función dentro de una misma idea: captar atención, generar contexto, mostrar una oportunidad o condición, y orientar la acción cuando corresponda.

No diseña piezas, no indica estilos visuales y no produce video, animaciones ni assets.

## Antes de redactar

1. `copywriter-workflow` ya ejecutó `audit-copy` sobre el texto, imágenes, post o contexto recibido. Esta skill adapta secuencia; no repite la auditoría salvo que el insumo cambie.
2. Lee `sources/source-registry.md` y los guardrails aplicables.
3. Consulta `knowledge/library/` cuando la story mencione una feature o flujo conocido.

## Workflow

1. Toma del editor el tema, la finalidad y las condiciones que deben conservarse.
2. Identifica si la story adapta una pieza existente o comunica una idea nueva con contexto suficiente.
3. Completa la hoja de diseño persuasivo común. Cuando haya varias motivaciones confirmadas, usa `knowledge/principles/motivation-portfolio.md` para ordenarlas como beats, no como una lista. La primera pantalla y la siguiente se evalúan dentro de `evals/commercial-coherence-grader.md`: la primera abre tensión, contraste, pregunta o futuro deseable; la segunda la continúa antes de aterrizar la feature.
4. Distribuye una sola idea por pantalla. No cortes una frase larga entre varias pantallas solo para llenar una secuencia.
5. Construye progresión: tensión/interés, oportunidad personal, mecanismo o condición relevante, y acción cuando la finalidad lo requiera.
6. Ajusta la cantidad de pantallas a la complejidad real del mensaje; no fuerces un número fijo.
7. Ejecuta `evals/hard-gates.md`, `evals/commercial-coherence-grader.md` y `evals/decision-readiness-grader.md`; revisa que cada pantalla conserve la tesis de la primera y que fechas, precios, urgencia, disponibilidad, Gana Ya y demás condiciones sean verificables para esa pieza.

## Entrega

Entrega solo el copy por pantalla:

```text
Pantalla 1: ...
Pantalla 2: ...
Pantalla 3: ...
Acción: ...
```

Incluye una acción final solo cuando sea coherente con la finalidad y esté disponible para el usuario. Usa `modo variantes` únicamente cuando el editor pida A/B o ángulos estratégicos distintos.

## Límites

- No crear visuales, layouts, transiciones, stickers, encuestas ni guion audiovisual.
- No usar FOMO o urgencia de relleno.
- No convertir una condición de oferta en una promesa de compra, entrega, transferencia, garantía o resultado.
- No añadir frases que dependan de información que la pantalla o el contexto no confirme.
