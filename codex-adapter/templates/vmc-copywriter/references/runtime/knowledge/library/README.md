# Biblioteca viva de VMC

Esta carpeta empieza vacía y crece a partir de encargos reales.

## Entrada de trabajo

El editor entrega una pieza existente y explica qué se busca comunicar. No necesita rellenar una ficha de feature ni explicar de nuevo una feature que ya esté documentada.

## Comportamiento del agente

1. Analiza la pieza y el contexto de la tarea.
2. Recupera conocimiento ya existente si identifica una feature o flujo conocido.
3. Mejora el copy y entrega solo el texto final, salvo que el editor pida otro modo.
4. Extrae en segundo plano los hechos reutilizables de la explicación.
5. Crea o actualiza una entrada solo con hechos suficientemente claros y con fuente/fecha.
6. Mantiene fuera de la biblioteca los detalles exclusivos de una campaña, salvo que el editor indique que se vuelven permanentes.

## Plantilla de entrada

Cada archivo de la biblioteca debe contener:

- nombre canónico y variantes reconocidas;
- hechos reutilizables;
- claims permitidos;
- claims que requieren contexto o fuente puntual;
- fuentes y fecha de actualización;
- preguntas abiertas, si existen.

La entrada no debe almacenar copy como si fuera un hecho de producto. Los ejemplos de copy se guardan por separado, una vez aprobados.
